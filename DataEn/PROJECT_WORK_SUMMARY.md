# สรุปสิ่งที่ทำในโปรเจกต์

เอกสารนี้รวบรวมสิ่งที่ตรวจสอบ แก้ไข และเพิ่มในโปรเจกต์ระหว่างทำงานร่วมกัน

## ภาพรวมเดิม

- โปรเจกต์เป็นเว็บ Flask สำหรับค้นหาและแสดงข้อมูลพนักงานจาก PostgreSQL
- ใช้ Docker Compose เปิด PostgreSQL, pgAdmin และเว็บแอป
- ตาราง `employees` มีชื่อ นามสกุล แผนก เงินเดือน และวันที่เริ่มงาน
- เดิมเว็บค้นหาพนักงานตามแผนกได้ และมีข้อมูลพนักงานเริ่มต้น 70 คน
- โฟลเดอร์ `SQL/` เป็นสื่อและชุดข้อมูล TastyGo สำหรับฝึก SQL แยกจากฐานข้อมูลพนักงานของเว็บ

## งานที่ทำและเปลี่ยนแปลง

### 1. สำรวจโจทย์และโครงสร้าง

- อ่าน `command.md` และ `advanced-query-task.md`
- ตรวจดูโครงสร้าง Docker Compose, เว็บ Flask, เทมเพลต HTML, schema และข้อมูลตั้งต้น
- สรุปโจทย์ว่าให้เพิ่ม query ขั้นสูง 2 แบบ โดยไม่ใช้การเรียงตามเงินเดือนหรือค้นหาตามชื่อ และต้องอธิบายการทำงานบนหน้าเว็บ

### 2. เพิ่ม Advanced Query สองแบบ

- เพิ่ม query สรุปสถิติรายแผนก ได้แก่ จำนวนพนักงาน เงินเดือนเฉลี่ย เงินเดือนสูงสุด และต่ำสุด โดยใช้ `GROUP BY`, `COUNT`, `AVG`, `MAX` และ `MIN`
- เพิ่ม query แสดงพนักงานที่มีเงินเดือนสูงกว่าค่าเฉลี่ยของแผนกตัวเอง โดยใช้ subquery คำนวณค่าเฉลี่ยแยกแผนกด้วย `GROUP BY` แล้ว `JOIN` กับพนักงานเพื่อกรองผล
- เพิ่มปุ่มเรียก query และตารางแสดงผลในหน้าเว็บ
- เพิ่มคำอธิบายและตัวอย่าง SQL ของแต่ละ query ไว้บนหน้าเว็บ

### 3. แก้บั๊กผล query ว่าง

- พบว่า `web-app/app.py` อ่านผลด้วย `fetchall()` ซ้ำ ทำให้การอ่านครั้งที่สองได้รายการว่างและทับผลลัพธ์เดิม
- ลบการอ่านผลซ้ำออกแล้ว

### 4. เพิ่มพนักงานเป็น 300 คน

- เพิ่มไฟล์ `init/zz_more_employees.sql`
- ไฟล์สร้างข้อมูลพนักงานตัวอย่างเพิ่มได้สูงสุด 230 คน โดยจับคู่ชื่อกับนามสกุลจากรายการที่กำหนด แล้วสุ่มเลือกคู่ที่ยังไม่มีในตาราง รวมกับข้อมูลเดิม 70 คนเป็น 300 คนเมื่อเริ่มฐานข้อมูลว่าง
- กำหนด seed สำหรับการสุ่มเพื่อให้ได้ลำดับการเลือกเดิมเมื่อเริ่มฐานข้อมูลใหม่ด้วยข้อมูลตั้งต้นชุดเดิม

### 5. ปรับการ mount โฟลเดอร์ init

- เปลี่ยน Docker Compose ให้ mount `./init` ทั้งโฟลเดอร์ไปยัง `/docker-entrypoint-initdb.d`
- เมื่อ PostgreSQL เริ่มต้นบน data volume ว่าง จะประมวลผล `init.sql` ก่อน แล้วตามด้วย `zz_more_employees.sql` ตามลำดับชื่อไฟล์

## วิธีใช้งานที่เกี่ยวข้อง

เปิด PowerShell ในโฟลเดอร์โปรเจกต์ แล้วสร้างหรืออัปเดตเว็บแอปด้วย:

```powershell
docker compose up --build -d
```

เปิดเว็บที่ <http://localhost:5001> และดูสถานะคอนเทนเนอร์ด้วย:

```powershell
docker compose ps
```

หากมี PostgreSQL volume เดิมอยู่แล้ว ไฟล์ใน `/docker-entrypoint-initdb.d` จะไม่ถูกรันซ้ำโดยอัตโนมัติ การเพิ่มพนักงานจากไฟล์ใหม่ในกรณีนั้นให้รันครั้งเดียวด้วย:

```powershell
docker compose exec -T postgres psql -U postgres -d labdb -f /docker-entrypoint-initdb.d/zz_more_employees.sql
```

การรันคำสั่งนี้ซ้ำจะเพิ่มพนักงานจากคู่ชื่อและนามสกุลที่ยังไม่มีในตารางได้อีกสูงสุด 230 คนต่อครั้ง จึงอาจทำให้จำนวนพนักงานเกิน 300 คน แม้จะไม่เพิ่มคู่ชื่อที่มีอยู่แล้ว ควรรันเพียงครั้งเดียวหากต้องการชุดข้อมูล 300 คน และการใช้ `docker compose down -v` จะลบฐานข้อมูลที่เก็บใน volume

## สถานะการตรวจสอบ

- ตรวจสอบจากไฟล์แล้วว่า query ทั้งสองใช้คอลัมน์ที่มีอยู่ในตาราง `employees`
- ตรวจสอบแล้วว่าไฟล์ตั้งต้นมีพนักงาน 70 คน และไฟล์ SQL เพิ่มข้อมูลสุ่มได้สูงสุด 230 คน โดยเลือกจากคู่ชื่อและนามสกุลที่ยังไม่มีในตาราง
- ยังไม่ได้ทดสอบ query ในฐานข้อมูลหรือเปิดเว็บผ่าน Docker ในสภาพแวดล้อมนี้ เนื่องจากการเชื่อมต่อ Docker API ถูกปฏิเสธ

### 6. ปรับ query พนักงานเงินเดือนสูงกว่าค่าเฉลี่ยแผนก

- แก้ `web-app/app.py` ใน action `above_department_average`
- ใช้ subquery คำนวณ `AVG(salary)` แยกตามแผนกด้วย `GROUP BY department` แล้ว `JOIN` ค่าเฉลี่ยกลับเข้ากับพนักงานแผนกเดียวกัน
- กรองด้วย `e.salary > d.avg_salary` และแสดงค่าเฉลี่ยปัดเป็นทศนิยม 2 ตำแหน่ง
- ปรับตารางผลลัพธ์ให้แสดงคอลัมน์ตาม query ได้แก่ ชื่อ นามสกุล แผนก เงินเดือน และค่าเฉลี่ยแผนก
- ตรวจสอบ diff ของไฟล์แล้ว ยังไม่ได้รันแอปหรือทดสอบ query กับฐานข้อมูล

# งาน: เพิ่ม Advanced Query 2 อันในเว็บแอป (Docker)

## สรุปโจทย์

- เอาไฟล์จากไดร์ฟที่ได้รับ (`init`, `n8n`, `SQL`, `web-app`, `docker-compose.yml`) ไปรันด้วย Docker
- เปิดพอร์ตของ `web-app` ดูหน้าเว็บ ตอนนี้ค้นหาได้แค่ **ตามแผนก**
- ต้องเพิ่ม **query ที่แอดวานซ์กว่าเดิมอีก 2 อัน**
- **ห้ามใช้** "เรียงตามเงินเดือน" และ "ค้นหาตามชื่อ" (เป็นตัวอย่างที่อาจารย์ยกให้ แต่ไม่ให้ทำ) ต้องคิดอันใหม่เอง
- ข้อมูลตอนนี้มีพนักงาน 70 คน จะเพิ่มคนอีกก็ได้ (ไม่บังคับ แต่ได้พิจารณาพิเศษ)
- ใช้ AI ช่วยได้เต็มที่ แต่ต้อง **อธิบายผ่านหน้าเว็บ** ได้ว่าเพิ่มอะไร ทำอะไร
- ถ้าทำดีและอธิบายเข้าใจ รอบหน้าอาจารย์อาจตรวจแบบผ่านๆ

## ขั้นตอนที่ต้องทำ

### 1. เตรียมระบบ

- [ ] โหลดโฟลเดอร์ทั้งหมดจากไดร์ฟ
- [ ] รัน `docker compose up -d`
- [ ] เช็คว่าคอนเทนเนอร์ขึ้นครบ (`docker compose ps`)
- [ ] เปิดหน้าเว็บที่พอร์ตที่กำหนดใน `docker-compose.yml` แล้วลองใช้ของเดิม

### 2. ทำความเข้าใจของเดิมก่อน

- [ ] ดูโฟลเดอร์ `SQL` และ `init` ว่ามีตารางอะไร คอลัมน์อะไรบ้าง (เช่น พนักงาน, แผนก, เงินเดือน, วันเข้างาน, ตำแหน่ง)
- [ ] ดูใน `web-app` ว่า query แผนกเขียนไว้ตรงไหน และหน้าเว็บเรียกใช้ยังไง
- [ ] จะได้เขียนของใหม่ตามรูปแบบเดิม

### 3. คิด query ใหม่ 2 อัน

ไอเดีย (ต้องไม่ซ้ำกับเรียงเงินเดือน / ค้นหาชื่อ):

| ไอเดีย | เทคนิค SQL |
|---|---|
| สถิติรายแผนก: จำนวนคน, เงินเดือนเฉลี่ย/สูงสุด/ต่ำสุด | `GROUP BY` + aggregate |
| พนักงานที่เงินเดือนสูงกว่าค่าเฉลี่ยของแผนกตัวเอง | subquery / window function |
| จัดกลุ่มตามอายุงาน (<1 ปี, 1-3 ปี, 3+ ปี) | `CASE WHEN` |
| Top N ของแต่ละแผนก (เช่น 3 คนเงินเดือนสูงสุดต่อแผนก) | `RANK()` / `ROW_NUMBER()` |
| แผนกที่มีคนน้อยกว่า X หรือไม่มีใครเลย | `LEFT JOIN` + `HAVING` |

**ที่แนะนำให้เลือก**

1. **สถิติรายแผนก** (`GROUP BY` + aggregate)
2. **พนักงานที่เงินเดือนสูงกว่าค่าเฉลี่ยแผนกตัวเอง** (subquery / window function)

เหตุผล: ใช้เทคนิคต่างกัน อธิบายง่าย ดูมีความคิดจริง แต่ต้องเช็คก่อนว่าตารางมีคอลัมน์ที่ต้องใช้ครบ

### 4. สั่ง AI ให้ทำ

ก๊อปโค้ดใน `web-app` ที่เกี่ยวกับ query แผนกเดิม พร้อมโครงสร้างตารางจากโฟลเดอร์ `SQL` แล้วสั่งประมาณนี้:

```text
นี่คือเว็บแอปที่ค้นหาพนักงานตามแผนกได้อย่างเดียว
ช่วยเพิ่ม query ขั้นสูง 2 อันตามรูปแบบเดิม:
(1) สถิติรายแผนก จำนวนคน เงินเดือนเฉลี่ย สูงสุด ต่ำสุด
(2) รายชื่อพนักงานที่เงินเดือนสูงกว่าค่าเฉลี่ยของแผนกตัวเอง

ให้เพิ่มปุ่ม/ฟอร์มบนหน้าเว็บ แสดงผลเป็นตาราง
และใส่ข้อความอธิบายบนหน้าเว็บว่า query แต่ละอันทำอะไร
ใช้ SQL อะไร ให้ผลลัพธ์อะไร
แล้วบอกด้วยว่าแก้ไฟล์ไหนบ้าง
```

### 5. ทดสอบ และเพิ่มข้อมูล (ไม่บังคับ)

- [ ] รีสตาร์ท: `docker compose down` แล้ว `docker compose up --build -d`
- [ ] ลองกดทุก query ดูว่าผลถูกต้อง
- [ ] (โบนัส) เพิ่มพนักงานให้เกิน 70 คน ให้ AI สร้าง `INSERT` ชุดใหญ่
- [ ] **ข้อควรระวัง**: ถ้าแก้ไฟล์ในโฟลเดอร์ `init` ต้องล้าง volume ก่อน (`docker compose down -v`) ไม่งั้นข้อมูลใหม่จะไม่เข้า

### 6. ทำส่วนอธิบายบนหน้าเว็บ (สำคัญที่สุด)

ใต้แต่ละ query ให้มีกล่องข้อความบอกว่า:

- **ทำอะไร**: ตอบคำถามอะไร
- **SQL ที่ใช้**: แสดงโค้ดให้ดูเลย
- **เทคนิคที่ใช้**: เช่น `GROUP BY`, subquery และเหตุผลที่เลือก
